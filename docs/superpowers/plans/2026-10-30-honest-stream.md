# Honest card stream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every card states an honest base rate. Native card priors are shrunk across keys, PEAD cards
carry a measured net-excess base rate, the live PEAD journal keeps the raw EPS pair, GEX never
fabricates IV or expiry, and one ledger records which research windows are spent.

**Architecture:**
- A pure empirical-Bayes shrink in `research/setups/card_prior.py` derives the frozen
  `card-stats-prior-v2` from v1's committed moments.
- An offline research module recomputes PEAD v2's events in `net_excess_r_v1` and freezes a
  digest-pinned `pead-base-rate-v1`. The PEAD catalog source loads it and attaches it to drift cards.
- GEX keeps missing model inputs as NaN.
- Docs only for the ledger.

**Tech Stack:** Python 3.14, uv, pandas/numpy, pydantic v2, pytest. SQLite unit tests; no schema change.

**Spec:** `docs/superpowers/specs/2026-10-30-honest-stream-design.md`

## Global Constraints

- No provider, network or database access in `scripts/card_stats_prior.py` or `scripts/pead_base_rate.py`;
  tests keep the blocked-network guards.
- No new migration (head `008_alpha_pipeline`); no new journal stream; no `card_policy` mode change.
- Every new field on a stored model (`CardKeyStats`, `CardEvidence`, provenance blocks) is optional with
  default `None`: stored snapshots/notifications from before this PR must still validate and render.
- Loader failures raise with one fixed literal message, never a path or file content.
- Type names only in readiness details, Telegram text and journal reasons.
- `uv run pre-commit run --all-files` clean; ruff C408/PLC0415 are strict (no `dict()` calls, no
  function-local imports).
- Implementers stage only and report; the controller commits.
- Repo-local paths in committed files; never `/Users/...` absolute paths in docs or JSON.

## Review Focus

1. **A pre-PR stored snapshot or notification without the new fields.** It must render exactly as
   before. T1 adds a test that renders a v1-era `CardEvidence` payload.
2. **The prior or base-rate file digest not configured, mismatched or invalid.**
   - The native card shows the existing unavailable behaviour.
   - The PEAD card shows `• PEAD base rate: unavailable` and is still sent.
   - T1 and T3 add tests for each.
3. **A hand-edited v2 prior whose `mean` disagrees with `replay_mean`/`shrinkage`/`cross_key_mean`.**
   `load_prior` refuses it. T1 adds a test.
4. **An option chain where every contract lacks IV.** No profile or regime is produced, and the
   callers' existing error path reports it. T4 adds a test at the fetcher boundary.
5. **The PEAD re-label disagreeing with the study's `labels.csv.gz`.** The script refuses to write the
   base-rate file. T2 adds a test with one perturbed label.

**Shrinkage** (spec §3.1):
- `A = between_key_tau²`, where `between_key_tau = pooled_tau`;
- `w_k = 1/(A + se_session_k²)`;
- `μ = Σw_k·replay_mean_k / Σw_k`;
- `B_k = A/(A + se_k²)`;
- `mean_k = μ + B_k·(replay_mean_k − μ)`.

`shrink_across_keys` reads the raw value from `replay_mean`. A v1-derived entry enters with
`replay_mean = mean` (the v1 mean) and `shrinkage = 1.0` before shrinking. Every other field is copied
unchanged.

**Statistics** (spec §3.2):
- **Rows:** LONG direction only, with finite `net_excess_r`.
- **Leg:** `is_leg`.
- **Control:** all rows. P2 per leg event is its `net_excess_r` minus the mean `net_excess_r` of all
  rows in the same session; the cell `p2_mean` is the mean of that difference.
- **Standard errors:** session-clustered, i.e. the sd of per-session means divided by √sessions, as
  `card_prior` computes them.
- **Recent window:** `recent_from = 2025-01-01`.
- **τ:** `between_quarter_tau` over leg rows.
- **Expected figure:** `B = τ²/(τ² + se_recent²)`, giving `expected_mean = B·recent.mean` and
  `expected_se = √B·recent.se_session`.
