# Test contamination and position valuation — 2026-09-15

## Findings

Tests supplied temporary paths, but global `DATABASE_URL` took precedence. A
separate connectivity test explicitly targeted the application PostgreSQL DB.
Synthetic SPY, QQQ and /MES records entered the running daemon's state.

The daemon matched an unrelated earlier 39-share SPY sell to two synthetic
10-share SPY entries. Each false close reported $2,595.49. Together with synthetic
QQQ and /MES closes, contaminated realized profit was **$5,765.98**. These are
application bookkeeping artifacts, not evidence of those synthetic broker trades.

IWM's proposed entry was stored as $285.18, but Alpaca's actual average short entry
was $285.40. At 105 shares that alone caused a **$23.10** unrealized-P&L difference.
The old report also used an independent IEX last trade; Alpaca's account valuation
can have a different price and observation time. The precise earlier Telegram and
dashboard snapshots cannot be reconstructed because no valuation audit existed.

A real prior 39-share SPY trade remained only in legacy SQLite after the PostgreSQL
switch. The explicitly reviewed broker entry and exit show a **$86.44 loss**;
SQLite had recorded a **$166.53 loss** using an estimated exit.

## Corrections

- Pure settings models, explicit runtime loading, credential-free test config,
  temporary databases, blocked Python/native network I/O, and disposable opt-in PG.
- Entry fill synchronization and exact parent/leg matching with full quantity,
  symbol, side and timestamp checks; streams trigger the same reconciliation path.
- Shared CLI/Telegram broker valuation, source/time audit, and visible mismatches.
- Conditional database close gates alerts; manual close waits for actual fill.
- Environment/account provenance, audit events, and reversible signal quarantine.
- Safe dry scans and non-actionable, labeled diagnostic notifications.

The repair tool `scripts/repair_incident_20260915.py` previews and validates a saved
read-only snapshot before applying changes. It quarantines confirmed fixture rows
1, 2, 6–11, preserves their original values in audit, and restores the explicitly
reviewed historical SPY trade without modifying SQLite or calling broker/Telegram
APIs. It is idempotent and refuses mismatched evidence. Broker entry synchronization
corrects currently active entries from the exact order IDs.

## Verification and remaining limits

Regression tests cover this order mismatch, partial exits, duplicate close events,
cost basis/valuation, quarantine exclusions, and manual close acceptance versus
fill. SQLite and dedicated PostgreSQL migration tests exercise the audit schema.
Tests cannot access the runtime database or Telegram credentials.

Audit notification results distinguish a closed trade from successful delivery;
there is not yet a transactional notification outbox/retry worker. Unknown external
exits and partial-fill combinations remain tracked for review rather than being
inferred from old orders. See [development follow-ups](development-notes.md#high-priority-follow-ups).

## Follow-up: Telegram responsiveness

Two `httpx.ReadError` events were observed after the first repaired daemon
restart: `/status` response delivery at 19:26 UTC and `/positions` response delivery
at 19:31 UTC. Full traces confirm those replies failed after handlers received the
commands. The operator reported occasionally repeating commands. Review also found
synchronous data calls on the async event loop and no application error handler or
shared outbound retry policy.

Shared transport retries, command/request correlation, polling recovery/freshness
and event-loop stall telemetry now cover this gap. Blocking provider, correlation,
simulation quote, schema and Monte Carlo paths were moved to worker threads;
scans remain serialized. See the architecture review for remaining command-queue,
executor-capacity and outbox limitations.
